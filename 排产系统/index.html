这是什么 / 怎么用

解决什么：把「本公司产能 + 供应商交期 + 临时插单」三类信息放在一起，自动算出每张订单的物料到位日、占用天数、计划开始/完成日、是否逾期，并标出哪条产线哪天爆产能。

用法：① 在「数据录入」填产能、供应商提前期、订单（产线/供应商用下拉选）；② 切到「排程结果」看自动排程与逾期；③ 切到「产能负荷看板」看热力图，红格就是超载的产线/日期；④ 临时插单：在订单里加一行并勾「插单」，系统立即重算，看红格出现在哪天，据此决定插哪个空档。

数据存哪：全部存在你浏览器本地（localStorage），不清缓存就不会丢；也可用「导出数据」存成 JSON 备份，或「导入数据」恢复。多人协作需后端/数据库，本 MVP 为单机版。

部署到 GitHub Pages（免费上线，团队网页访问）：

  1. 在 GitHub 新建一个仓库（如 aps），把本 index.html 推上去；
  2. 仓库 Settings → Pages → Source 选 main 分支根目录 → Save；
  3. 几分钟后访问 https://你的账号.github.io/aps/ 即可。

多人实时协作（Supabase，免费）：

  1. 注册免费 Supabase 账号（supabase.com），新建项目，进入 SQL Editor 执行下面的建表语句；
  2. 项目 Settings → API 拿到 Project URL 和 anon public key；
  3. 把这两个值填进本文件脚本顶部的 SUPABASE_URL / SUPABASE_ANON_KEY；
  4. 重新部署到 GitHub Pages，同事打开同一网址即可同时看、同时改、数据每 6 秒自动同步。

建表 SQL：
create table aps_state (id text primary key, data jsonb not null, updated_at timestamptz default now());
alter table aps_state enable row level security;
create policy "open" on aps_state for all using (true) with check (true);

安全提示：上述策略允许任何人（持 anon key）读写，适合内部小团队；若需权限控制可改为按登录用户限制。anon key 设计上可公开，嵌入前端无碍。

注：本系统用自然日计算占用天数（未扣除周末）；如需按工作日、或做同产线严格串行排队，可在此基础上继续扩展。
